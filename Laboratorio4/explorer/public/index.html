REFERENCIA DIDÁCTICA

Glosario Blockchain y árboles Merkle Patricia

Consulta el significado de los campos que aparecen en el explorador. Los ejemplos se refieren a Ethereum y a la red local Hardhat.

transactionsRoot Raíz de transacciones

Hash raíz del Merkle Patricia Trie que compromete las transacciones incluidas en un bloque. Las claves se derivan de RLP(índice) y los valores son las transacciones serializadas.

receiptsRoot Raíz de recibos

Hash raíz del trie de recibos de ejecución del bloque. Los recibos contienen, entre otros datos, el estado o resultado apropiado al formato, el gas acumulado, los logs y su filtro bloom. No equivale a los saldos.

stateRoot Raíz del estado global

Hash raíz del trie que representa el estado completo de Ethereum después de ejecutar el bloque: cuentas, saldos, nonce, hash de código y raíz de almacenamiento de cada cuenta. No incluye únicamente los cambios de ese bloque.

MPT / Trie Merkle Patricia Trie

Un trie organiza valores por rutas derivadas de sus claves. El Modified Merkle Patricia Trie de Ethereum combina organización por prefijos, compresión de rutas y hashes verificables. No es el árbol binario de Merkle que suele usarse para explicar Bitcoin.

RLP Recursive Length Prefix

Formato determinista de codificación de secuencias de bytes y listas. Ethereum lo utiliza para representar ciertas estructuras y para construir claves como RLP(índice de transacción).

Clave RLP Índice codificado, no clave privada

En el trie de transacciones, es la posición de la transacción dentro del bloque, codificada con RLP: índice 0 → 0x80; 1 → 0x01; 2 → 0x02; 3 → 0x03. No firma operaciones ni da acceso a cuentas.

Keccak-256 / Hash Huella criptográfica

Keccak-256 genera una huella de 32 bytes. Ethereum la emplea para hashes de transacciones, nodos y otros compromisos. Un cambio en los bytes de entrada normalmente cambia el resultado.

Root hash Hash raíz

Valor que compromete criptográficamente los datos de un trie. Si se reconstruye el trie con los mismos datos y reglas, se obtiene la misma raíz. Para confiar en ella también hay que confiar en el encabezado que la contiene.

Proof / Prueba de inclusión Ruta verificable

Conjunto de nodos que permite comprobar que una clave y su valor pertenecen a un trie con una raíz dada. La vista de este explorador muestra una ruta de prueba, no el árbol completo.

Nibble Cuatro bits

La mitad de un byte: un dígito hexadecimal entre 0 y f. Las rutas de los tries Patricia se expresan como secuencias de nibbles.

Branch / Extension / Leaf Tipos de nodos del trie

Branch: ramificación con 16 posibles hijos y un valor opcional. Extension: comprime un segmento compartido de la ruta. Leaf: nodo terminal que asocia el resto de una clave a su valor.

Transaction Index / Hash Posición e identificador

El índice es la posición de la transacción dentro del bloque, comenzando en cero. El hash identifica los bytes firmados de esa transacción. Son valores diferentes.

Block Hash / parentHash Identidad y enlace del bloque

blockHash identifica el encabezado de un bloque. parentHash apunta al hash del bloque anterior, vinculando los encabezados de la cadena.

Receipt / Logs Recibo y eventos

Un recibo es el resultado registrado de ejecutar una transacción. Los logs son registros emitidos por contratos, consultables para seguir eventos en la red.

Gas / gasUsed Costo computacional

Gas es la unidad que mide el trabajo realizado por la EVM. gasUsed refleja cuánto se consumió efectivamente. En Hardhat se utiliza ETH ficticio para las pruebas.

Nonce Contador de cuenta

En una cuenta externa, cuenta las transacciones enviadas y ayuda a ordenar y evitar reutilizaciones. No debe confundirse con una clave privada.

EVM / ABI Ejecución e interfaz

EVM: Ethereum Virtual Machine, ejecuta contratos. ABI: Application Binary Interface, describe cómo codificar llamadas a funciones y decodificar resultados y eventos.

JSON-RPC / Chain ID Comunicación e identificación

JSON-RPC: protocolo con el que la web y PowerShell consultan el nodo por HTTP. Chain ID: identificador de red; Hardhat local usa normalmente 31337 (0x7a69).

EDR / Automining Simulador de Hardhat

EDR: Ethereum Development Runtime, motor de Hardhat. Automining: creación automática de bloques al enviar transacciones. Esta red local no ejecuta consenso P2P real.

Para interpretar las pruebas: que calculatedRoot coincida con transactionsRoot verifica la coherencia de los datos reconstruidos con la raíz del bloque; no demuestra que los datos de una API externa sean verdaderos.
